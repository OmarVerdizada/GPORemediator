# GPO Remediator 3.17.8

Rollback inspection now follows a stable, non-authenticating connection identifier instead of the identity of a browser JSON object. A normal 15-second heartbeat renews the idle lease without invalidating the restore form. A new connection, changed operation/backend or expired assessment still invalidates cached inspection. Submitting a typed restore confirmation performs a fresh read-only recovery assessment before opening the final confirmation dialog. Newly detected drift blocks submission and displays its reason; native restore still rechecks drift and permissions under its lock. Scope computers selects the optional refresh targets after a confirmed full-GPO restore; it is not a per-computer restore operation.

User-right evidence no longer counts an unavailable/empty endpoint result as a second measured value. Mismatch or unavailable details open automatically. Live LSA mismatches identify missing and unexpected SIDs. Unavailable probes report language-mode restrictions, compilation versus read stage, and a native error code when available. No security-template export is substituted for live LSA assignments and no endpoint permissions or language mode are changed automatically. The read-only API requires the documented [LSA policy access rights](https://learn.microsoft.com/en-us/windows/win32/api/ntsecapi/nf-ntsecapi-lsaenumerateaccountswithuserright).

Firewall verification compares both the endpoint policy registry value/type and the resultant [ActiveStore profile](https://learn.microsoft.com/en-us/powershell/module/netsecurity/get-netfirewallprofile). Matching resultant values cannot conceal a missing, different or incorrectly typed policy input. Read denial remains unavailable evidence. This does not establish log-file creation, actual traffic logging or agreement with an external scanner whose collected value has not been supplied.

These fixes do not establish the live winning GPO for DC-01 or the external scanner's failure cause. A measured user-right mismatch remains a mismatch until the endpoint state changes and a new measurement confirms it. No live AD access is available in this checkout.

Read-only Re-verify after a non-domain snapshot restore now collects current endpoint values as `OBSERVED`, independently of snapshot restoration. Existing backups did not capture pre-change effective endpoint values, so these observations cannot certify an endpoint undo. Restoring an undefined security setting can leave an applied endpoint value in place, as described in [Microsoft's security policy persistence documentation](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/security-policy-settings/security-policy-settings). The application does not guess an old value or silently reset audit policy. The result heading explicitly says GPO snapshot restored.
