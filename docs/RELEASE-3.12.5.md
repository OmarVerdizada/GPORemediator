# 3.12.5: control-specific verification and Firewall review

Post-change verification now groups measured GPO, replication and sampled endpoint results separately from policy-source attribution and refresh telemetry. Scheduled refresh and unavailable winning-GPO evidence use blue informational cards with visible explanations. Mismatches and refresh failures remain red; missing endpoint evidence and pending replication remain amber. The selected control and sampled-endpoint scope is explicit. A matching value is never promoted to proof of the winning GPO or completion of a scheduled refresh. Current server stages replace the duplicate legacy four-box summary, which could disagree with content-aware replication evidence. Older records retain their fallback summary.

Firewall manual checks now show only the selected profile and property alongside its policy registry value. For example, 9.1.5 shows Domain.LogMaxSizeKilobytes, 9.1.6 shows Domain.LogBlocked, and 9.2.4 shows Private.LogFileName. This avoids mistaking unrelated properties printed in the old full-profile command for the selected control's result.

The review of all 23 Firewall mappings found no demonstrated writer defect. All use computer-policy registry settings under the appropriate Domain/Private/Public profile, DWORD booleans and sizes, and a String log path. Minimum log size remains a >= comparison. No arbitrary policy version, additional CSE, local policy override or live domain change was introduced. See [Firewall review and diagnostic boundaries](FIREWALL-REVIEW-3.12.5.md).

Regression fixtures reproduce a compliant Domain log size with disabled logging, a noncompliant independent Private path, case-insensitive equivalent paths, stronger/weaker sizes, unavailable values and native probe failures. They execute the real endpoint verification function with mocked Windows/AD calls. Existing all-control fixtures exercise publication/read-back/idempotence for 394 automated mappings and matching/mismatching endpoint evidence. Browser checks cover the revised presentation; all 405 generated manual commands are parsed by Windows PowerShell 5.1 without execution.

Command results are preserved in `docs/audit/3.12.5-test-results.json`. These are local build and synthetic regression checks, not live AD certification.
