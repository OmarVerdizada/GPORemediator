# GPO Remediator 3.17.10

The result page reports **GPO applied successfully** when the requested GPO value and target link are confirmed. Endpoint verification is a separate count: for example, **1 of 2 verified · 1 unavailable**, with the unavailable host named. All confirmed target values produce **Applied and verified**. A real endpoint mismatch stays prominent. A missing link, interrupted write or unavailable publication never receives the successful publication headline. These labels do not change benchmark compliance or endpoint evidence.

Successful snapshot restoration reports **Rollback completed successfully**, independently of endpoint refresh. The operation drawer keeps failed refresh visible and displays computer and signed-in user processing separately. Detailed restore fingerprints, source attribution and per-host probe diagnostics remain available in expandable sections. Generic permanent “More evidence needed” labels are replaced with specific endpoint counts or source-attribution status. Offline results retain recorded-evidence wording and neutral presentation. A stale sample-verified flag cannot override an unavailable inspected host.

Rollback refresh with delegated credentials executes computer `gpupdate /target:computer /force /wait:-1` over the existing authorized Kerberos/WinRM path. It independently schedules `Invoke-GPUpdate -Target User` for signed-in user policy. A user scheduling failure preserves completed computer processing and the verified GPO restoration, while remaining a failed combined refresh. The signed-in user's context is never substituted with the remoting operator. Without delegated credentials, the existing both-half scheduling path remains; scheduling is never promoted to completion. Pinned membership, bounded batches, drift checks and explicit refresh authorization remain enforced. See Microsoft's [gpupdate parameters](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/gpupdate) and [Invoke-GPUpdate scheduling and Target behavior](https://learn.microsoft.com/en-us/powershell/module/grouppolicy/invoke-gpupdate).

Refresh evidence optionally includes `computerState` and `userState`; absent fields preserve older evidence serialization. LSA failures include safe exception/category identifiers and compiler error codes when present. Raw exception text, including PowerShell throw-generated error IDs, is excluded from endpoint diagnostics. No application-control or execution-policy restrictions are bypassed. An endpoint on which the native read-only probe cannot compile remains unavailable; it is never declared verified from a stored INF.

The application still distinguishes GPO snapshot restoration from endpoint undo. An older Not configured snapshot did not capture pre-change effective LSA assignments. Restoring that snapshot does not prove those assignments were removed from an endpoint. Fresh live evidence is required after deployment.
