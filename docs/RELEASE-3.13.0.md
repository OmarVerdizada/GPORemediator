# 3.13.0: inspectable standalone PowerShell in every control overview

Every one of the 405 control overview pages exposes copyable manual PowerShell procedures or a read-only review. The new standalone GPO panel shows domain/DC, selected GPO, target DN, policy scope, concrete registry/template/audit fields, types and requested values. Automated controls include a scrollable full script, Preview/Apply script selectors, copy and UTF-8 BOM `.ps1` download, plus separate native verification and optional endpoint gpupdate commands. It works with bundled mappings when disconnected; missing target fields are explicit placeholders that stop execution until filled. Mobile policy rows use a stacked layout.

For the 394 automated controls, the standalone procedure includes 46 actual production worker/security-template functions. `scripts/Build-ManualEngine.ps1` extracts their AST dependency closure without executing it. `Build-Portable.ps1` regenerates the inspectable bundle from the canonical worker, security module, mappings and manual wrapper template. The regression checks its parity, so a copied policy writer cannot silently become a separate outdated implementation.

Preview is the default and performs no GPO write, backup, link change or refresh. Apply requires the exact control ID and GPO GUID at a console confirmation, validates the writable DC/domain and control scope, obtains the per-GPO lock, takes a full GPO backup, rechecks drift, uses the shared writer, manages the selected link and reads the GPO back. Failures after writing begins remain REVIEW_REQUIRED with the backup retained. No endpoint success or refresh completion is inferred. No credentials are embedded, and no app/API or downloaded helper script is required for manual execution.

The remaining 11 manual/review-only controls retain their boundary: seven user-right controls expose a read-only selected-GPO report and native checks for role-specific review. Four endpoint/local-policy controls keep their existing dedicated copyable procedures and execution prerequisites; no irrelevant GPO target template is added above them. No unreviewed blanket privilege-assignment writer was added. Manual execution runs as the operator's current Windows account; app RBAC/allowlists/job history do not govern an external PowerShell session. Viewing, changing script mode, copying and downloading never submit a server job.

See [manual procedure usage and recovery limits](MANUAL-POWERSHELL.md). Stop the previous app, extract the entire new package and start `GpoRemediator.cmd`; confirm version 3.13.0. Existing configuration, history and backups are preserved. The embedded runtime is rebuilt alongside the UI.

Validation includes 405 actual overview renders, 800 exact PowerShell 5.1 parses, complete isolated Preview/Apply procedures for Registry, RegistrySet, SecurityTemplate, AdvancedAudit, domain account and HKCU mappings, literal custom-value escaping, backup ordering, publication read-back, idempotence, cancellation, failed backup, drift, partial-write and read-only-DC rejection. Browser checks verify visible/copy/download parity, the PS1 BOM, no POST requests from script interaction, and desktop/mobile layout. Dated command evidence is in `docs/audit/3.13.0-test-results.json`. These are build and synthetic regression checks; no live AD policy was changed or certified.
