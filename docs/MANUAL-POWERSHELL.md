# Manual PowerShell procedures

Open a control's **İcmal / Overview** tab. Manual scripts or dedicated guides are available in every populated benchmark section, including disconnected browsing. Empty supplemental categories contain review guidance rather than invented control writers. The steps below apply to the 394 standalone GPO writers. The four dedicated endpoint/local-policy guides retain their own target, preflight, copyable commands and recovery instructions; they do not require a fictitious GPO selection.

1. In **Hədəf və tətbiq / Target & apply**, choose the actual domain GPO and target OU/domain and enter any organization-specific value. Return to Overview. The panel uses the current selection, not a previous operation's target. Changing controls resets script mode to Preview.
2. Review the target facts and requested policy fields. Copy **Yoxlama skripti / Preview script** or download its `.ps1` file. Run it in **Windows PowerShell 5.1 on the selected writable domain controller**, with ActiveDirectory and GroupPolicy modules and the appropriate Windows permissions. The selected writable-DC/domain check rejects an accidental member-server or other-DC session. Fill in any `REPLACE_WITH_...` fields when using an offline template.
3. Inspect the read-only output: current/requested policy values, target, GPO and all existing link scopes. To change it, choose **Tətbiq skripti / Apply script**, review its visible code, copy/download it and run it yourself. The console asks for `APPLY <control ID> <GPO GUID>` before backup or writes. Merely selecting this script in the application does not execute it.
4. Keep the printed backup ID, directory and manifest. After GPO read-back, use the panel's separate native value check on the intended endpoint/user session. Domain account checks read Get-ADDefaultDomainPasswordPolicy from the selected DC. Optional gpupdate commands run on the endpoint and target the appropriate computer/user policy half.

The full script is inspectable text, not an encoded payload or a call back to this application. Its mapping writer, audit CSV canonicalization, CSE metadata/version handling, numeric bounds and preservation of stronger include policies come from the same canonical functions as automated Apply. Preview and Apply differ in the visible `$Action` value. The mapping JSON and target header are literal data; quotes and organization text are escaped. Downloaded files have a UTF-8 BOM for Windows PowerShell 5.1, including non-ASCII organization values.

The default backup root is `C:\ProgramData\GpoRemediator\Backups` on the DC; edit `$BackupRoot` if necessary. The lock coordinates cooperating operations that use this same backup root and DC. It cannot lock out GPMC or another administrator. Fingerprints are rechecked before writing and after backup; avoid concurrent policy administration. A GPO change affects every existing link, not only the displayed OU. Filtering, WMI, enforcement and inherited/winning GPO evidence still need review. Manual execution uses the current Windows account and does not inherit the application's execution identity, RBAC, allowlists, approval workflow or durable job history.

A full Backup-GPO snapshot is taken before the first policy/link write. The manifest stores the original direct link, pre/post fingerprints, backup ID and phase. If a write or read-back fails after WRITING begins, partial changes may exist; the script retains REVIEW_REQUIRED and rethrows the error. Inspect the current GPO and backup in GPMC before recovery. Restoring a full GPO snapshot can replace unrelated changes, and **Backup-GPO does not restore OU links**; use the saved `beforeLink` metadata for a separately reviewed link restore. The manual procedure does not perform an automatic rollback or certify safe recovery after external drift.

Manual/review-only controls publish a read-only GPO report rather than an automatic write recipe. Existing endpoint/local-policy guides remain available for four controls. Seven user-right assignments require a role-specific membership decision; the panel does not suggest clearing their principal lists. Configuration/read-back is separate from endpoint processing, replication, restart/logon/service prerequisites and runtime enforcement. A manual run is not automatically recorded as an application operation or compliance evidence.

Developer regeneration: `powershell.exe -NoProfile -File scripts/Build-ManualEngine.ps1`. Use `-Check` for parity without writing files. `node scripts/Test-ManualRemediation.cjs` parses the exported procedures and runs isolated native-command fixtures, not live AD.
