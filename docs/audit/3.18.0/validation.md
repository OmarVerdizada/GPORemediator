# 3.18.0 validation

All 75 build/regression command checks passed on their final runs. The complete exact-write matrix covers 405 controls / 413 policy-scope cases, and exact endpoint verification covers 413 mappings / 1,148 synthetic cases. This release repeats both matrices. Source mappings and ordinary single-control forms retain their existing behavior. Results, SHA-256 log references and selected PASS evidence are retained beside this document.

The four C# suites cover existing identity isolation, submission consent, durable queue recovery, single-control refresh chains and write boundaries. Added batch regressions cover mixed User/Computer previews, distinct refresh contexts, read-only multi-control verification, related domain-account ordering, exact approved values, lockout-threshold ordering, missing/invalid dependency rejection, first-snapshot recovery and removal of stale forward claims from restored members. An initial run failed compilation on a nullable dereference in the new test assertion; the assertion was corrected and the suite passed again. The initial record remains nested under initialAttempt. This correction did not change production behavior.

The native batch test executes the real rollback dispatcher against protected-manifest-shaped private fixtures and mocked directory/GPMC APIs. It validates all selected AD post-values before restore, restores related saved values in one AD cmdlet call, rejects unselected/unknown properties and invalid pairs, persists plural baselines, checks every restored AD property independently, supports explicit repeated recovery and rejects external AD changes. The normal exact matrix continues to exercise the original single-control worker. Endpoint batching additionally exercises restored-root/member refresh context separation and rejects a foreign GPO or a forward-only targeting projection before endpoint remoting. Existing 201-host pagination, delegated computer refresh and separate signed-in-user scheduling remain covered.

The new browser suite runs the real frontend with mocked HTTP jobs. It checks User/Computer selection, a 5,000-OU inventory with bounded search options and retention of a selected value, no writes before Preview and explicit approval, stored values and link intent, automatic refresh selection, per-control unavailable evidence, light/dark desktop/mobile rendering, durable resume without write replay, batch rollback and navigation from a restored member to the full recovery receipt. Screenshots show synthetic example.test/test.local fixtures only. Mobile preview values are stacked in readable cards. Existing recovery, targeting, result, offline, theme and accessibility-related frontend regressions remain in the full run. A final batch-only recovery presentation refinement routes restored children to the first complete snapshot receipt; ordinary recovery actions retain their prior path.

The portable Windows x64 backend is compiled and packaged from the current backend source. The first final source-match check caught the package fingerprint becoming stale after the batch-only recovery presentation refinement: the backend package fingerprint also includes frontend source. The portable package was rebuilt, then runtime integrity, source match, PowerShell syntax and production package validation were rerun. Earlier attempts remain recorded. Runtime checksum, installer boundaries, dependency advisory completeness and secret checks are also checked. No production credential storage, package dependency or database schema is introduced by the feature.

AD, GPMC, WinRM, gpupdate and remote endpoint values are mocked in these regressions. Private filesystem operations, native local read-only LSA testing, compilation and browser rendering run for real. No post-feature live AD bulk Apply, live paired-account rollback, signed-in user RPC processing or effective endpoint undo was performed. A restored Not configured GPO does not establish an unknown pre-change endpoint value. A batch is sequential rather than transactional: a failure stops remaining steps while completed changes and their backups remain recorded. Fresh authorized live endpoint evidence is still needed after deployment.
