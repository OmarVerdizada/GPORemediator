# GPO Remediator 3.17.9

Live rollback diagnostics showed that native Import-GPO preserved the user-right SID sets but reordered their entries, removed blank lines and moved Version/Privilege Rights blocks around Registry Values in GptTmpl.inf. The original byte-based restore comparison treated this representation change as an unsuccessful restore. CSE metadata and the selected scope link were unchanged.

Restore verification now uses a separate comparison for this case. Known security-template SID assignments are canonicalized as sets; Unicode/Version metadata and the privilege block are compared independently of their placement. Other policy blocks retain their order and contents; other setting values and files remain protected. Only the documented UTF-16LE/BOM representation is canonicalized; see [MS-GPSB encoding requirements](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-gpsb/fa15485d-ae9f-456e-a08f-81f2e5725a7e). Ambiguous duplicate assignments, unrecognized principal syntax, invalid encoding and unsupported syntax fall back to byte comparison. The original fingerprint algorithm remains the default and still protects pre-restore external-change checks. A changed SID, changed other setting or changed unrelated file remains a mismatch.

New operations retain an independent pre-write restore-content fingerprint. Existing records can recover through read-only Verify or rollback inspection only after the complete retained native backup is authenticated against the saved original content fingerprint. If the backup omits GPT.INI, the live version-normalized file can fill that slot only when the complete reconstructed raw fingerprint still matches the original record. Corrupt or unprovable backups remain unverified. Native [Import-GPO](https://learn.microsoft.com/en-us/powershell/module/grouppolicy/import-gpo) remains the restore mechanism.

Results, exported integrity-hashed evidence and the UI now retain separate content, computer/user extension, scope-link and AD-domain restore checks. A failed first restore check stays review-required; it is no longer mislabeled as a later external drift without a verified restoration baseline. The operation drawer displays the restoration target rather than the original forward request.

This verifies GPO snapshot restoration. Earlier records did not capture pre-change effective endpoint values. Returning a security setting to Not configured can leave an applied value on the endpoint; current endpoint observations remain separate from proof of an endpoint undo. See [Microsoft's security-policy persistence documentation](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/security-policy-settings/security-policy-settings).

After updating, open the original failed rollback operation and select Re-verify live state or Check rollback availability. Authenticated formatting-only differences can then be recognized without reapplying the forward change. Run the explicit post-rollback refresh after the snapshot is confirmed. Production deployment and endpoint convergence still require fresh live evidence.
