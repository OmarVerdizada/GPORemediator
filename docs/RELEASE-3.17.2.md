# GPO Remediator 3.17.2

The native transport now emits one `GPO_RESULT:` JSON frame on its own line. Ordinary stdout from modules/native commands can no longer corrupt the final response. Duplicate final frames fail closed; output remains bounded and unexpected envelopes/data never become a successful operation. Legacy clean JSON responses remain readable. Stderr is drained and classified without persisting or returning its contents. Missing/invalid responses report exit code, last validated stage, response length and a safe classification; execution-policy and parse failures get distinct guidance rather than an unconditional signing suggestion.

The bootstrap also recognizes `gpoCheck` inside dictionary-shaped InformationRecord MessageData. It previously inspected only PSObject properties and could discard those live checking events. Both dictionary and object-shaped records are supported, and informational output is kept separate from the operation data.

The environment review no longer has a ten-character minimum. Any nonempty trimmed note is accepted; blank notes, notes over 2048 characters and unapproved policy fields remain blocked. This applies to frontend validation, C# mappings and standalone manual-script generation.

The primary plan comparison now shows **Stored GPO value** with its source GPO name/ID beside **Desired**. An absent value is **Not configured in selected GPO**. Link state and endpoint applicability remain separate, so an equal stored/requested value does not establish application to an unlinked OU. Failed current-value reads are **Read unavailable**, without claiming the setting is absent. Domain-account plans retain the actual AD-before value plus the separate stored GPO context.

Domain sign-in passes the entered delegated credential over private subprocess stdin to a Kerberos/WinRM session on the pinned DC. The worker checks DC/domain identity, modules and the execution account's domain SID, then reads GPO/OU inventory. Readiness and per-target write checks are separate. The password is not written to the database, generated scripts or application files: the active connection retains an ASP.NET Data Protection ciphertext in server memory and decrypts it for each invocation. It is removed on disconnect, expiry or service restart. Idle expiry is 15 minutes since connection API use and absolute expiry is two hours. Browser cookies contain random tokens, not the password. Audit records include account identity and operations. Data Protection keys persist under `%ProgramData%\GpoRemediator\Data\Keys`, protected with Windows DPAPI; those files are encryption keys, not saved domain credentials.

The transport defect was reproduced using the actual Windows PowerShell 5.1 bootstrap, mocked remoting, module stdout without a newline, live InformationRecord checks and both success/failure replies. This reproduces the reported transport-error class; the user's actual management-host stdout/stderr was not supplied, so its exact extra output or process-exit cause is not asserted. See [validation](audit/3.17.2/validation.md). No live AD changes are part of local validation.
