# GPO Remediator 3.17.3

User Rights Assignment checks now call `LsaEnumerateAccountsWithUserRight` on each pinned endpoint and compare current assigned account/group SIDs with the requested set. `secedit /export /mergedpolicy` is no longer accepted as the live verifier for privilege assignments. Its use for other supported security settings remains. If LSA cannot be read, verification stays pending; the application does not fall back to a matching export and claim the live assignment is verified. The native helper requests only POLICY_LOOKUP_NAMES and POLICY_VIEW_LOCAL_INFORMATION and releases handles/buffers. Copied manual checks use the same read-only LSA source and retain the wrong-host guard.

For the supplied 2.2.16 incident, the Default Domain Policy report contains the requested four principals and the previous DC-01 export contained matching SIDs. That establishes the reported stored/exported configuration. It does not establish why Sechard failed, its measurement method or whether its result was fresh. The new LSA measurement supplies independent current assignment evidence; it does not certify an external scanner result or attribute the winning GPO.

Windows 1726/PSSessionStateBroken is reported as a broken endpoint session. Nested Win32 codes are inspected through wrapped errors without exposing exception text. A JobFailure without an identifiable cause is explicitly reported as an unavailable remote job result, rather than suggesting that secedit or policy permissions have been proven to fail. Result summaries show refresh and value-check failures together, inspected host names and distinct unavailable-value labels. Stored GPO provenance is rendered on separate lines.

Refresh progress now emits `REFRESH` check frames for each host as its endpoint session opens and as completion/failure is recorded. These are separate from actual-value evidence. A completed gpupdate still does not establish the endpoint policy value. The reported PSLWSUS01 connection failure cannot be repaired by a repository change alone; endpoint WinRM/PowerShell event evidence from the recorded DC-to-host path is still needed to determine the underlying session-break cause. No firewall, WinRM, trust or endpoint-security setting is weakened automatically.

Once the production write gate is enabled with an explicit configured boundary, a successful server-owned Preview that checks target write access and readiness can authorize the exact selected GPO/OU/endpoint-OU pair within that connection. This removes the repeated “Authorize this GPO + scope” transition for new previewed targets. It does not rewrite configuration, restart the service, change the credential lifetime, authorize a GPO/OU cross-product or share a grant with another connection/operator. Read-only scans and failed readiness/access checks grant nothing. Apply consent, protected-GPO confirmation, stale-plan checks, AD write/link checks, backups and rollback guards remain mandatory. Grants expire with the 15-minute idle/two-hour absolute connection lifetime or disconnect/restart.

Validation and limits are recorded in [audit/3.17.3/validation.md](audit/3.17.3/validation.md). The native LSA helper compiles under Windows PowerShell 5.1; the local test identity received access denied (5), which was propagated without claiming a measurement. Success/mismatch/empty/failure cases use explicit LSA doubles and do not change local or deployment policy.

Primary API references: [LSA enumeration](https://learn.microsoft.com/en-us/windows/win32/api/ntsecapi/nf-ntsecapi-lsaenumerateaccountswithuserright), [LSA policy access](https://learn.microsoft.com/en-us/windows/win32/api/ntsecapi/nf-ntsecapi-lsaopenpolicy), [security database export](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/secedit-export).
