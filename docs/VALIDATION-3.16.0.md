# 3.16.0 validation

56 distinct command checks passed; zero final failures. The full 55-check offline audit ran, a full pilot-runner transport-fixture regression was added, and affected checks were repeated after final UI/package refinements. [Canonical logs, SHA-256 hashes and resolved initial failures](audit/evidence/3.16.0/test-results.json) preserve the evidence and its scope.

- Diagnostic tests execute the trusted functions and actual remote probe against local cmdlet doubles. They cover selected/competing/unknown sources, recorded security/WMI filtering, unavailable RSoP, independent native/event evidence, exact AD/file targets and rejection before remote access for an endpoint outside scope.
- FGPP tests cover snapshot additions/removals, renamed/moved identities, departures, case-insensitive subjects, fresh unapproved reconciliation previews, Apply/Verify/Rollback, membership drift, competing policies and interrupted mutation recovery.
- Real browser tests load the application with recorded local responses: 10,000 operations, 10,000 audit events and 5,000 OUs. They check page limits, later-page navigation, full-list search, exact target selection, link-priority intent, safe HTML encoding and read-only diagnostic calls. New screen controls meet 4.5:1 text contrast in both themes; desktop/mobile layouts are checked. The wider theme/navigation matrix covers every route at 320/390/768/1440 pixels.
- Installer tests run the actual package engine and installer against small fixture archives and a fake service API. They cover failed-first-install retry, complete update, preserved external state, safe activation rollback, active-operation stop rejection, incompatible schema, tampered components and archive traversal. No real application installation or ProgramData data was changed.
- The actual live-pilot entry point runs in child PowerShell processes with a fake HTTP transport: full lifecycle, denied baseline, interrupted Apply response and different restored endpoint values. Failure cases cannot claim successful certification; uncertain Apply is not blindly rolled back. Safety helpers reject remote credential destinations, protected/shared GPOs, oversized inventories, restart controls and no-ops.
- Rollback computer refresh is exercised across all 201 pinned endpoints in four bounded requests; per-host failures remain visible. Existing backend, authentication, backup ACL, remediation, mapping, recovery, source integrity, package and dependency checks pass.

The packaged runtime and frontend were rebuilt from the final source. Every application component is covered by the release manifest. Source/runtime fingerprints and runtime ZIP hash checks pass. Screenshot review: [light desktop](ui/3.16.0/desktop-light.png) · [dark mobile](ui/3.16.0/mobile-dark.png).

The AD environment is elsewhere. **No live AD GPO, endpoint, PSO or delegation was modified or validated here.** Run the prepared pilot on a dedicated OU/GPO in that environment before drawing conclusions about its live configuration lifecycle. Installation rollback changes the active application version, not policy or database history.
